## Summary

Implement scheduled flag state changes and scheduled change-request applications for FlagManagment. Users with `RELEASE_MANAGER` or `ADMIN` roles can schedule a flag to turn ON/OFF (or an approved change request to be applied) at a specific future UTC timestamp. A polling-based Go background worker (30-second tick) processes due schedules within the 60-second SLA (SC-001). Conflict detection prevents duplicate pending schedules per flag. A new `scheduled_changes` PostgreSQL table stores the lifecycle, and a full REST API (5 endpoints) plus React UI (badge + dialog) complete the feature.

## Key Technical Decisions

### 1. Scheduler Architecture

A `Scheduler` struct is initialized in `main.go` and started as a goroutine:

```
main.go → scheduler.Start(ctx)
  └─ time.NewTicker(30 * time.Second)
       └─ on each tick:
            1. Query: SELECT * FROM scheduled_changes WHERE status='PENDING' AND scheduled_for <= NOW()
            2. Fan out to bounded worker pool (N=20 goroutines)
            3. Each worker: execute action → update status='EXECUTED' → log audit entry
            4. On error: log and continue (do not crash)
```

Startup catchup: the first tick query also catches any overdue schedules from before a restart.

### 2. Execution Dispatch

```
Scheduler.executeOne(sc ScheduledChange):
  CASE target_type:
    FLAG         → FlagStateRepo.Update(enable/disable) inside WithTx
    CHANGE_REQUEST → ChangeRequestService.ApplyScheduled(crID) inside WithTx
  THEN:
    ScheduledChangeRepo.MarkExecuted(sc.ID, now)
    AuditService.LogAction(systemActorUUID, "SCHEDULED_EXECUTION", sc.TargetType, sc.TargetID)
    CacheClient.PublishRulesetUpdate(sc.EnvironmentID)
```

### 3. Conflict Detection

```
ScheduledChangeService.Create():
  1. BEGIN TRANSACTION
  2. SELECT ... FOR UPDATE WHERE target_id=? AND status='PENDING'  -- advisory lock
  3. If exists → return ErrPendingScheduleExists (→ HTTP 409)
  4. INSERT INTO scheduled_changes ...
  5. COMMIT
  (Partial unique index at DB level provides final safety net)
```

### 4. RBAC Wiring

```
POST   /environments/{envId}/scheduled-changes  → RequireRole("RELEASE_MANAGER")
GET    /environments/{envId}/scheduled-changes  → RequireRole("VIEWER")
GET    /scheduled-changes/{id}                  → RequireRole("VIEWER")
PATCH  /scheduled-changes/{id}                  → RequireRole("RELEASE_MANAGER")
DELETE /scheduled-changes/{id}                  → RequireRole("RELEASE_MANAGER")
```
